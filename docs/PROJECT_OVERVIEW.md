## 1. 한 줄 소개

**RedFlag는 낯선 링크를 열기 직전에 휴대폰 안의 AI(Gemma)가 페이지를 읽고, 몇 초 안에 "위험한지"를 알려 주는 Android 앱입니다.**
더 확인하고 싶을 때만, 사용자가 직접 눌러 클라우드 에이전트(Claude Opus)에게 정밀 분석을 맡길 수 있습니다.

### 풀려는 문제
- 택배 문자, 중고거래 "안전결제", 기관 사칭 전화, 계정 정지 알림처럼 **링크 하나로 시작하는 사기**가 대부분입니다.
- 기존 방법은 사기를 **목록**에 의존합니다(예: Google 세이프 브라우징).
  - 실제로 모은 피싱 60건 중 **47건이 세이프 브라우징 목록에 없었습니다** (`eval/real/sb_missed_phishing.txt`).
  - 새로 만든 사이트, 검사기에는 다른 화면을 보여 주는 사이트, 호스팅 업체만 막은 사이트는 목록에 늦게 오르거나 오르지 않습니다.
- 페이지만 보는 검사기는 **사용자가 어떤 상황에서 링크를 받았는지** 모릅니다.
  같은 결제 페이지라도 "모르는 판매자가 중고거래 중에 보낸 링크"라면 위험합니다.

### RedFlag의 방식
1. **기기 안에서 먼저, 빠르게.** 링크를 열기 전에 숨은 브라우저로 페이지를 읽고, 기기 안 Gemma 4 E4B가 판단 근거를 채웁니다. 실기기 기준 Gemma 응답은 평균 약 4초입니다.
2. **점수는 코드가 매긴다.** AI는 "증인" 역할만 하고, 점수는 공개된 규칙 파일(`contracts/scoring_rules.json`)이 계산합니다.
3. **상황(맥락)까지 본다.** 링크를 연 앱, 받은 메시지, 사용자의 짧은 답을 함께 판단합니다. 맥락은 점수를 **더하기만** 합니다.
4. **클라우드는 사용자가 누를 때만.** 페이지 내용이나 대화가 자동으로 밖으로 나가는 경로는 없습니다.

## 2. 핵심 원칙

| 원칙 | 의미 | 강제하는 곳 |
|---|---|---|
| **모델은 증인, 점수는 코드** | Gemma·Opus는 정해진 항목(브랜드 사칭 여부, 요구하는 행동 등)만 답하고, 점수는 선언형 규칙이 계산 | `contracts/scoring_rules.json` + Kotlin/Python 쌍둥이 엔진 |
| **가산만** | v4 이후 규칙과 맥락은 점수를 올리기만 하고, 어떤 답도 다른 규칙이 준 점수를 지우지 못함 | 재채점 가드(점수 하락 불가), 벡터 테스트 |
| **실패하면 절대 "안전"이 아님 (D3)** | 분석이 끝나지 못하면 최소 30점(주의). 모델 없음·로드 실패·파싱 실패·타임아웃·추출 실패 모두 해당 | `analysis_incomplete` clamp, `FailSafeLiteTest`, `FailSafeInvariantTest` |
| **계약이 단일 원천** | 규칙·스키마·브랜드·게이트 목록·추출 스크립트는 `contracts/` 한 곳에만 있고, 앱과 백엔드가 같은 파일을 읽음 | 빌드 시 리소스 복사, 계약 테스트 |
| **쌍둥이 구현** | 같은 로직을 Kotlin(앱)과 Python(백엔드)으로 두 번 구현하고, 같은 벡터 파일을 둘 다 통과해야 함 | `scoring_vectors.json`, `followup_vectors.json` 등 |
| **클라우드는 요청 시에만** | `AnalysisController.requestCloud()` 하나만 클라우드로 가는 길이며, 고급 분석 버튼에서만 호출됨 | `NoAutomaticCloudTest`(소스 검사) |
| **모델은 화면 문장을 만들지 않음** | 동의 문구·질문은 정해진 목록의 ID로만 고름. 페이지 인젝션으로 가짜 입력창이 뜨는 것을 막음 | `contracts/context_catalog.json` |

## 3. 사용자 경험

### 3.1 진입점

| 진입점 | 동작 |
|---|---|
| **다른 앱에서 링크 탭** (문자·카카오톡 등) | RedFlag가 기본 브라우저 역할을 맡아 먼저 받습니다. 알려진 사이트는 화면 없이 바로 Chrome으로, 낯선 사이트는 검사 화면을 띄웁니다. |
| **Chrome 안에서 이동** | 접근성 서비스가 Chrome 주소창을 보고, 낯선 사이트면 페이지 위에 **덮개**를 씌워 검사합니다. 판정 전에는 페이지를 누를 수 없습니다. |
| **앱 안 링크 검사** | 홈 "링크 검사" 칸에 링크나 받은 메시지를 통째로 붙여 넣습니다. 열지 않고 먼저 확인하며, Chrome을 자동으로 열지 않습니다. |
| **공유 / 글자 선택 메뉴** | 메시지를 [공유 → RedFlag로 검사]로 넘기거나, 글자를 선택해 검사합니다. 공유된 글만 받아 처리합니다. |
| **최근 기록** | 이전 판정을 다시 보고 [다시 검사]할 수 있습니다. |

### 3.2 판정 단계

| 점수 | 단계 | 화면 |
|---|---|---|
| 0–29 | 안전 | 잠깐 확인 후 그대로 진행(링크 탭·덮개). 앱 안 검사는 [Chrome에서 열기] 버튼 |
| 30–59 | 주의 | 근거 목록 + [그래도 열기] / [돌아가기] + 고급 분석 추천 |
| 60–84 | 위험 | 차단 화면, 근거, 진동 |
| 85–100 | 매우 위험 | 차단 화면, 근거, 강한 진동 |
| — | 확인 못 함 | "사이트가 응답하지 않아요" / "사이트가 검사를 막았어요" / "제때 확인하지 못했어요" — 절대 안전으로 표시하지 않음 |

화면에는 점수 게이지 애니메이션, 근거(빨간 깃발) 목록, 판정 이유 한 줄(헤드라인)이 나옵니다.
맥락으로 점수가 오르면 "+50 · 받은 상황 반영" 칩이 붙고, 게이지가 이전 점수에서 이어서 올라갑니다.

## 5. 분석 파이프라인

### 5.1 Gate (게이트) — `android/core/.../gate/`
- **주소 정규화**: WHATWG 규칙, 스킴 없는 주소는 https, IDN은 punycode로, 비슷한 글자(키릴 а 등) 검출.
- **등록 도메인**: Public Suffix List(사설 영역 포함)로 `pages.dev`, `github.io` 같은 호스팅을 구분합니다.
- **알려진 정상**: 브랜드 38개의 공식 도메인, Tranco 상위 10만(해시셋), 12시간 안전 캐시.
- **낯선 경우**: 단축 URL은 렌더링 없이 리다이렉트만 따라가 최종 주소를 다시 게이트에 넣습니다. UGC(공용 게시판·블로그)는 알려진 도메인이어도 검사합니다.
- **세이프 브라우징 v5**: 목록에 있으면 페이지를 열지 않고 즉시 95점입니다.

### 5.2 페이지 읽기 — 숨은 WebView + Chrome 화면
- **숨은 WebView** (`OffscreenExtractor`)
  - 격리 설정: 별도 프로필(쿠키·저장소를 매번 삭제), JS 브리지 없음, 다운로드 차단, http(s) 외 스킴 차단, Chrome과 같은 UA.
  - 판정 시점: 페이지 구조(DOM)가 준비되면 0.7초 더 기다려 화면이 그려진 뒤 `contracts/extract_page.js`를 실행합니다.
    느린 사이트도 기다리며, 30초는 아예 안 열리는 페이지에 대한 상한일 뿐입니다.
  - 추출 항목: 제목, 보이는 글, 숨은 글, 폼(필드 종류·action), 링크, **데이터 전송처**(폼 action, fetch/XHR/beacon, 전송 스크립트 속 URL).
- **페이지 상태 판단** (`PageStates`, 코드 규칙):

  | 상태 | 예 | 처리 |
  |---|---|---|
  | loaded | 사이트 자체 페이지 (오류를 흉내 낸 사기 페이지 포함) | 분석 |
  | challenge | Cloudflare "Just a moment...", DDoS-Guard | 최대 12초 기다림 (Chrome 덮개 아래에서는 3초 후 화면 읽기) |
  | blocked | "you have been blocked", 403 Forbidden, ModSecurity | Chrome 화면 읽기 |
  | host_warning | Cloudflare "Suspected Phishing/Malware" | **판정**: 최소 95점 |
  | unavailable | 5xx, 사이트 없음, 계정 정지 | "사이트가 응답하지 않아요" |

  가짜 "사람인지 확인하세요" 피싱 페이지는 업체 표시나 403/429/503 상태가 없으면 CDN 검사로 보지 않고 분석합니다.
- **Android 세이프 브라우징**: WebView가 자체 보호로 페이지를 막으면 그것도 세이프 브라우징 판정(95점)으로 씁니다.
  Chrome은 경고하는데 공개 API는 "목록에 없음"이라고 답하는 경우를 잡습니다.
- **Chrome 화면 읽기** (`ChromeScreenReader`)
  - 숨은 브라우저가 막히면, 접근성으로 Chrome이 실제로 보여 주는 글과 입력칸을 읽어 분석합니다.
  - 다른 앱에서 누른 링크라면 Chrome에서 덮개를 씌운 채 열고 그 화면을 읽습니다.
  - 숨은 브라우저는 거부됐는데 Chrome에는 입력칸이 보이면 **클로킹**(검사기에 다른 화면) +35점입니다.
  - 한계: 화면에 보이지 않는 숨은 글과 폼 전송처는 이 경로에서 알 수 없습니다.

### 5.3 Gemma (기기 안) — `android/core/.../gemma/`, `lite/GemmaEngine.kt`
- **모델·런타임**: `gemma-4-E4B-it.litertlm` (3.66 GB), LiteRT-LM 0.18.1, GPU(실패 시 CPU), 추측 디코딩, greedy, thinking 끔.
- **Turn 1**: `redflag-gemma-test/system_prompt_v2.txt`로, 맥에서 검증한 프롬프트를 바이트 단위로 그대로 씁니다.
  - 입력: `<signals>`(코드가 잰 값)와 `<untrusted_page>`(페이지 글, 데이터로만 취급).
  - 10개 항목: claimed_brand, brand_matches_domain, page_type, requested_actions, urgency_or_threat, too_good_to_be_true, addresses_ai_analyzer, verdict, confidence, evidence.
- **복구**: 파싱은 됐지만 일부 항목이 빠진 답은 보수적으로 메웁니다(FeatureRepair). 메운 경우 결과는 최대 59점(주의 이하)으로 묶이고, '안전'은 될 수 없습니다.
- **후속 턴**: 모두 페이지 글 없이 짧은 **별도 대화**입니다. Turn 1을 건드리지 않고, 인젝션 노출도 줄입니다.
  - **D (전송처 관계)**: 개인정보가 다른 도메인으로 갈 때 "같은 회사 / 알려진 서비스 / 무관"을 고릅니다.
  - **T2 (맥락 필요?)**: 네이티브 도구 호출로 자동 맥락 요청, 사용자 질문 요청, 불필요 중 하나를 고릅니다. 맥에서 형식 준수율 236/236.
  - **T3 (맥락 판단)**: 사기 시나리오, 목적과 페이지 요구의 일치 여부, 발신자 위험을 판단합니다. 근거 인용은 원문에 있어야만 채택합니다.

### 5.5 맥락 분석기 — `docs/plans/context_analysis.md`
1. **출발 앱 분류**: 링크를 연 앱(referrer)이나, 그 링크가 담긴 알림으로 메신저·문자·메일 등을 구분합니다.
2. **필요 여부 결정**: 코드가 제외 / 필요 / 괜찮음을 정하고, 괜찮음이면 Gemma T2에게 두 번째 의견을 묻습니다.
3. **자동 맥락**: "맥락을 분석해도 될까요?" 동의 후, 링크가 담긴 메시지와 그 앞 대화 몇 개를 메모리에서만 읽습니다. 알림 버퍼는 30분입니다.
4. **사용자 맥락**: 정해진 질문(U1–U4)과 빠른 답 칩, 300자 자유 입력. [상황 직접 입력]은 항상 열려 있습니다.
5. **판단과 재채점**: Gemma T3 판단 뒤 같은 판정 ID로 다시 채점하며, 점수는 내려가지 않습니다.
- 모든 단계에 [건너뛰기]와 [다시 묻지 않기]가 있습니다. 전화·계좌번호는 `#`로 가리고, `<` `>`는 바꿔 태그 탈출을 막습니다.

### 5.6 Cloud (정밀 분석) — `backend/`
- **API**: FastAPI `POST /v1/analyze`, SSE로 trace와 report를 실시간 전송합니다.
- **페이지 단계**: Docker Playwright 샌드박스(비루트, 읽기 전용, 입력·제출·다운로드 금지)에서 페이지를 엽니다.
  Opus 에이전트가 RDAP·crt.sh·세이프 브라우징·web_search·추가 탐색(2회)으로 조사한 뒤 `submit_report`로 답합니다.
  결과는 URL별로 6시간 캐시합니다.
- **사용자 맥락** (`docs/plans/manual_url_check.md` §5)
  - 보내는 것: 사용자가 직접 쓴 설명과 질문 답, 붙여 넣은 메시지(숫자 가림), 출발 앱 종류, 기기의 판단 결과.
  - **알림에서 읽은 대화 원문은 보내지 않습니다.**
  - 페이지 분석 캐시에는 맥락을 섞지 않습니다. Opus 맥락 판단을 1회 따로 하고, 기기 판단과 위험한 쪽으로 합칩니다.
  - 서버 DB·로그·trace에 원문이 남지 않음을 테스트로 확인합니다.
- **클로킹 비교**: 기기가 본 화면과 샌드박스가 본 화면이 다르면 +35점입니다.
- **예산**: 하루 Opus 호출 상한이 있고, 실제 호출 수를 DB에 기록합니다.

- 모델 답은 정해진 값(enum)으로만 받습니다.

## 10. 실행 방법 (요약 — 전체 절차는 `dev-log/MORNING.md`)

1. **빌드·설치**: `cd android && ./gradlew :app:installDebug` (JDK 17)
2. **모델**: 앱을 한 번 실행해 모델 폴더를 만든 뒤 `gemma-4-E4B-it.litertlm`을 push합니다. `adb shell mkdir`로 만들면 앱이 읽지 못합니다.
3. **권한**: 기본 브라우저 역할, 접근성(RedFlag 링크 보호), 알림 접근(선택).
4. **백엔드(정밀 분석)**: `cd backend && DEMO_MODE=1 docker compose up -d --build` → 폰에서 `adb reverse tcp:8000 tcp:8000`, `tcp:8081 tcp:8081`(데모 페이지).
   USB가 다시 연결되면 reverse가 사라지므로 다시 걸어야 합니다.
5. **발표용 설정**: 개발자 옵션 → "매번 다시 검사(발표용)". 이미 분석한 사이트도 매번 다시 검사합니다.
6. **데모 페이지**(로컬 전용, 디버그 빌드만): 중고 안전결제·원격지원·택배 재배송·경품 이벤트·DBS 사칭·M365 숨은 지시문·클로킹 등. 홈의 개발자 옵션에서 바로 열 수 있습니다.

## 12. 알려진 한계와 다음 과제

| 항목 | 상태 |
|---|---|
| **비슷한 이름의 가짜 도메인** (예: robiox[.]com[.]gr = 가짜 Roblox) | Gemma가 같은 도메인으로 착각하고, 브랜드 목록에 없으면 못 잡음. 제안: 코드로 비슷한 도메인 검출(A안), 승인 대기 |
| 정상 사이트 주의 오탐 45% (실제 120건 기준) | 모델 답 복구·파싱 실패가 원인. 실패 시 안전 불가 원칙의 대가로, 개선 과제 |
| Chrome 화면 읽기 | 숨은 글·폼 전송처를 볼 수 없음 (일부 규칙만 적용) |
| Gemma 페이지 상태 판단 | 측정상 이득 없음, 가짜 확인 화면 피싱을 오판해서 꺼 둠 |
| 주소 점(.) 경로(`/s/./x`) | 게이트가 정규화하지 않음. WebView 세이프 브라우징이 보완 |
| 클라우드 에이전트 사이트 직접 탐색 | 설계만 (`docs/plans/cloud_agentic_browsing.md`) |
| 프롬프트 인젝션 보강 | 설계만 (`docs/plans/prompt_injection_hardening.md`) |
| 시연 환경 | 폰 USB 재연결 시 adb reverse 끊김 |
